# 参考工作对照笔记

面向「给立理 S1 补一层技能运维能力」这个目标，把四篇工作的可用结论抽出来。
每篇只记三件事：它证明了什么、它的方法里哪部分我们能直接用、它的边界在哪里。

原文正文已提取到 `_refs/*.txt`，便于离线检索。

## 1. SkillNet: Create, Evaluate, and Connect AI Skills
**arXiv:2603.04448**　浙大 + 同济 + 东南 + 阿里/蚂蚁/腾讯等

### 它证明了什么
- 提出「技能」是 Agent 时代的模块化知识单元，替代符号逻辑与参数化知识两条老路。
- 在 ALFWorld / WebShop / ScienceWorld 三个环境上，接入技能库后平均奖励 +40%、交互步数 -30%，
  且在 DeepSeek V3.2 / Gemini 2.5 Pro / o4 Mini / Claude Sonnet 4.6 四个模型上都成立。
- **SkillNet-Gym 暴露的关键短板**：前沿 Agent 在真实社区技能池上做
  「技能检索」与「技能编排」时表现很差 —— 检索完整度在个位数到 30% 区间，
  一旦要求把检索到的技能组织成依赖保持的工作流，硬任务分数进一步崩塌。
  论文原话是 "Frontier Agents Exhibit Weak Skill Composition Ability in the Wild"。
- 另一个反直觉结论：官方精编技能**不一定优于**模型自己构建的技能，
  一次性压缩会带来信息损失。

### 能直接用
- **技能契约（Skill Contract）**：capability / inputs / outputs / use_when 四个字段。
  检索只读卡片不读全文，这是让技能池规模化的前提。
- **三层本体**：Taxonomy（分类）→ Relation Graph（依赖/组合/相似）→ Package（打包发布）。
- **五维评估**：Safety / Completeness / Executability / Maintainability / Cost-awareness，
  论文用 LLM 自动评估并与 3 名博士标注者做一致性验证（MAE < 0.03，QWK > 0.90）。
- **SkillNet-Fabric 的路由范式**：先把候选与证据组织成「任务级 Wiki」，再让 Explorer 在其中选最终集合。
  论文对 K=5 的对比：BM25 召回 30.0% → 稠密检索 54.4% → 检索+重排 61.4% → Fabric **67.91%**；
  FullCoverage 从 20.0% 提到 49.33%。

### 边界
- 500k+ 技能规模的检索评测靠的是图结构合成任务，与真实科研任务的分布有距离。
- 技能质量评估是 LLM 自动评，论文本身也承认它服务于"库级质量控制"而非"部署级安全校验"。

### 对本项目的映射
本原型实验一的数字与 Fabric 的趋势一致（BM25 77.5% → 完整方案 96.7%）；
技能契约、类型化关系、五维评估都已在 `skillnet/schema.py` 落地。
我们与论文的差异是：技能库规模小（51 vs 500k），因此绝对指标偏高，**相对收益在真实规模下应更明显**。

## 2. EvoScientist: Towards Multi-Agent Evolving AI Scientists
**arXiv:2603.08127**　华为

### 它证明了什么
- 现有 AI 科学家系统基本是**静态手工流水线**，不会根据积累的交互历史调整
  想法生成与代码生成策略，结果反复走同一条死路。
- 解法是三个角色加两个持久记忆：
  Researcher Agent（生成想法）、Engineer Agent（实现与执行）、
  Evolution Manager Agent（从交互历史里蒸馏经验）。
  记忆分两套：ideation memory 记录有效与无效的研究方向，experimentation memory 记录数据处理与建模策略。

### 能直接用
- **「进化管理」应当被显式建模成一个独立角色**，而不是散落在各环节的隐式更新。
- **记忆要分类型**：方向性经验（选题/路线）与操作性经验（怎么跑通）混在一起会互相干扰。
- 从失败里学：记忆里明确区分"可行方向"与"已证伪方向"。

### 边界
- 偏系统设计论文，端到端科学发现的成功率仍受限于底层模型。
- 三 Agent 架构的 token 成本高，适合长程任务，不适合高频短任务。

### 对本项目的映射
本原型的 `evolver.py` 相当于把 EMA 的职责单独抽出成模块，
并且把"从轨迹蒸馏"具体化为四种算子（distill / mutate / crossover / regenerate）。
**尚未实现的是分类型记忆** —— 当前技能库是单一池子，没有区分"路线类知识"与"操作类知识"，
这是后续可以借鉴 EvoScientist 改进的点。

## 3. Repo-To-Skill: Distilling GitHub Repositories Into AI4AI Skills (DisCo)
**arXiv:2609.02749**　BAAI + 中科大 + 人大 + 港理工

### 它证明了什么
- 提出「操作性知识（operational knowledge）」是自主研究 Agent 缺失的一层：
  它不告诉你"有什么方法"，而告诉你"这个方法在你的任务上该怎么用"。
  用论文的公式表达：`A_res = (M_θ, H, K)` —— 模型、harness，再加上知识层 K。
- **在模型、harness、下游执行预算全部固定**的前提下，加蒸馏技能后：
  MLE-bench **+134.3%**、PaperBench +34.4%、FrontierCS +9.2%、PassNet +14.0%。
  这个实验设计很关键 —— 它把技能层单独作为唯一变量隔离了出来。
- 蒸馏分两种形态：task-agnostic（离线，把领域常用仓库压成可复用技能）
  与 task-oriented（在线，针对具体任务现场生成）。产出 AREX-Skill Library：
  1,000 个仓库 → 5,000+ 技能，组织成 20 个领域、178 个能力族，由路由器分流。

### 能直接用
- **蒸馏四步**：Scope Capability → Ground Evidence → Construct Skill Graph → Verify & Refine。
  每一步都有明确产出物（能力边界、证据、技能图、验证记录与未解决缺口）。
- **"没有经过验证的技能不进库"** 是硬约束，且要把未解决的缺口显式记录下来，而不是假装完整。
- **声明式知识 ≠ 操作性知识**：论文、仓库文档说的是"什么成立"，
  技能要说的是"该怎么做"，后者必须从前者推导，不能直接搬。

### 边界
- 面向 ML 研究（MLE-bench 是 Kaggle 类任务），对实验科学（湿实验、仿真）的迁移性未验证。
- 蒸馏质量依赖源仓库质量，论文也提到源文档会随版本漂移。

### 对本项目的映射
本原型 `evolver.distill()` 实现的就是 task-oriented 蒸馏，
准入过滤对应 "Verify & Refine" 中的验证门槛。
**任务无关的离线蒸馏尚未实现** —— 这正是把 S1 的 300+ 工作流与内部文档批量转成技能的路径，
也是"技能库从人工维护变成自动积累"最直接的抓手。

## 4. COBRA-Skills: Contextual Bandit-Guided Evolution for Agent Skill Optimization
**arXiv:2609.11682**　港中深 + 天大 + 港科大（广州）+ NUS

### 它证明了什么
- 把技能优化组织成闭环：**有选择地评估技能 → 用实测反馈更新候选池 → 周期性生成新候选**。
- 关键设计：技能的**语义表示同时参与效果预测与探索决策**，
  因此一次评估的反馈会影响语义相近的未评估技能，不必逐个试。
- 六个基准、三种目标模型上取得所比较方法中的最高平均成绩；
  相对 SkillOpt，**优化成本下降 55%–58%**（Qwen 设置下教师用量从 1516 万降到 300 万 token）。
- 消融（表 4）：完整方法 73.5%，去掉老虎机选择 71.3%，去掉进化 71.1%，
  Best-of-30 71.0% —— **选择与进化两方面是互补的**，缺一各掉约 2.2–2.5 个百分点。
- 跨模型迁移（图 6）：36 组非对角迁移中 34 组正收益，说明技能保留了跨模型可复用的任务策略。

### 能直接用
- **优先级公式**：`优先级 = 预测收益 + 探索奖励`，
  即 `θᵀx + α·√(xᵀA⁻¹x)`（LinearUCB 风格）。探索系数 ν 有最优区间，论文默认 0.1。
  论文的敏感性分析：ν = 0.03 / 0.06 / 0.1 / 0.2 / 0.3 对应 69.8 / 70.8 / **73.5** / 71.1 / 70.8 ——
  **探索过强过弱都变差**。
- **最终输出按实测平均奖励选，不按预测分数选**；新生成的技能不继承父技能奖励，必须重新评估。
- **三种进化算子**：regeneration（从无技能轨迹独立提炼，打开新方向）、
  rollout mutation（依据刚获得的成功/失败轨迹局部修补）、
  crossover（高分技能作主干、另一高分技能作借鉴来源、低分技能作负面证据，不直接拼接文本）。
- **周期性更新而非逐轮重写**：用最小间隔 + 对数间隔约束，评估过 8 个以上不同技能才启用交叉。

### 边界
- 论文自己也说明：数据预算并非所有方法一致（COBRA 每基准 50 个优化样本，
  Trace2Skill/SkillOpt 用 53–170 个），美元成本依赖固定的计价口径。
- 平均领先不等于每个任务都最好：Qwen 的 SearchQA、GPT-Nano 的 LiveMath/SocialMaze
  都略低于 SkillOpt。

### 对本项目的映射
`skillnet/bandit.py` 是本篇最直接的实现（LinUCB + 随机选择消融），
`evolver.py` 实现了三种算子与准入过滤。
**尚未做的是"周期性更新"的调度策略**（最小间隔 + 对数间隔），
当前实验是按固定轮次触发，生产环境需要按预算动态调度。
