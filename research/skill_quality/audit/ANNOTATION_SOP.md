# 人工标注操作规程（待真实人员执行）

A/B 文件是空白模板，不是完成的标签。文件的 `score=null`、`status=unknown`、`reason=not_annotated` 必须保留到标注者亲自作答。

1. 指定两位独立真人和一位分歧仲裁者。匿名编号 A/B/C；记录背景与工时，不公开身份。不能用两个 Agent 或两个 LLM 代替两位人工。
2. 阅读 `configs/rubric-v1.yaml`、E02 协议与材料类型局限。D1 导出文件的首 20 行对应 `training_20_ids`，仅用于练习和讨论。修改 rubric 后创建新版本，不能重写已冻结历史文件。
3. 评分 0–4；证据不足选 unknown/null，不适用须写理由。每个 observed 维度引用实际源行、简短原文和判断理由；被隐藏的旧评分行不能用作证据。
4. 两位标注者使用各自文件的副本独立填写；不读取 baseline.jsonl、static_audits 或对方文件。不将原始不可变模板直接改写成标签。
5. 来源/许可维度另读对应 `*_provenance_review.jsonl` 和登记许可文件。许可声明不等于有效授权，不能确定时提交专家复核。
6. 不安装依赖、不运行包内脚本、不使用真实账号或密钥。此步骤评文档可观察质量；执行证据始终 `not_tested`。看到危险命令时要结合上下文区分“要求执行”和“示例/警告”。
7. 目前 D2 只有候选材料，正式盲测未冻结：112 个项目卡片和 88 个社区原文存在材料类型混杂。先解决来源问题并冻结 P1 协议，再决定最终 D2；不以这批文件已经存在为由跳过此门。
8. 独立完成后先计算仲裁前一致性和 unknown 覆盖率，再由 C 处理分歧。保存 A/B 原记录、仲裁理由、版本及 SHA。未完成时状态仍为 not_run。

盲法局限：导出隐藏算法评分、统计和 Stars；Skill 作者写在正文中的名字、链接、风格可能透露来源。来源/许可维度本来就不能完全隐匿来源。必须如实报告这些局限，而不是宣称已经实现严格身份双盲。
