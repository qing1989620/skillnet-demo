当前已完成首个离线工程关，尚未完成整项研究。方案 §7.1 禁止使用聊天中暴露的旧密钥；§7.8 和 §13 要求单独批准费用，当前批准额仍为 $0。

## 可继续的非付费工作

- 指定真实 A/B 标注者与仲裁人，在 D1 首 20 例上训练 rubric；不得把 Agent 输出当人工标签。
- 为正式 D2 增加合法、版本固定且与已有连接组独立的原始 Skill 来源，解决原文/项目卡片混杂；补充语义近邻与许可复核。
- 在新来源与任务族下准备受控 D4 输入、独立 verifier 和 mutation tests，冻结失败口径；Docker 不可用前不执行 Skill。

## 首次付费只申请 Probe-1

建议审批档位为 **最高 $10 USD**，这是待负责人确认的审批示例，不是已批准预算或预测账单。首轮仅做模型元数据/端点能力核对与合成输入探针，目标最多 3 个不同家族 × 2 次结构化请求，不发送真实 Skill、私有文件、标注答案或执行代码。

调用前必须完成：负责人撤销旧 key，并在本机以 `OPENROUTER_API_KEY` 安全提供新的限额 key；明确总预算及账户/日限额；核对实时模型、provider、定价和数据政策；补齐 generation 费用补账与账户/日控制。每次请求有独立预算预约，失败重试单独记账；未知费用立即停止，不能推断为免费。

Phase A 的 CLI 故意未开放付费/执行入口，真实 client 目前只有 Mock 验证。预算批准后，先在新配置版本实现并验证 Probe-1，再决定是否批准有人工答案和许可复核的 6–10 项 Probe-2。不能因为拿到 API key 就全库打分。

## 正式实验仍需的门

独立人工 gold → D1 校准并冻结 → D2 正式盲测；固定任务/受控环境/verifier → D4 Pilot → 费用与功效模拟 → 冻结 D5/D6、共同主终点与样本量 → 五主臂公平执行。任何门不满足，保留 not_run，不填写“提升”数值。
