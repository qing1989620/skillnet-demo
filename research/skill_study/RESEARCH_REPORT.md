**本轮完成：取得并核实 44 篇去重论文的正文，定向阅读方法、实验或局限片段，形成逐篇迁移表；对 200 个 D1 原始 Skill 包做完整性与接口审查，构造并检验 381 个受控命令案例；在 192 份历史检索捕获上运行 6 种集合选择方法，得到 1,152 条结果。随后经用户授权直连 DeepSeek 完成 54 次真实模型评价，53 次通过结构校验，389 条引用中 382 条通过严格定位核验。发现了明确的接口冲突、占位成功实现，以及多样性重排的负结果。当前没有独立人类质量金标准，也没有新一轮真实 Agent 执行收益，尚不能宣布达到论文级效果或普遍优于已有方法。**

## 1. 课题只保留两个主问题

**Q1：怎样核验一个 Skill 的质量和能力边界？** 要证明哪些声明有材料支持、哪些被实现反驳、哪些需要任务执行，不能把流畅文档或自报成功当作可靠能力。

**Q2：怎样让 SkillNet 在任务上更好？** 要在相同预算下选择适用、互补且有实证收益的技能与执行顺序，并防止更新后旧能力退步。节点更多、关系更密、检索更相似都不是最终成功标准。

二者的关系是：Q1 提供有版本、有条件、有不确定性的证据；Q2 研究这些证据是否真的改善选择和编排。不能把 Q1 的文档分数直接当成 Q2 的收益。

此前工程审计、冻结的 1,881 条对象、资源指纹、旧规则对照、引用校验、边界预检、盲标空白包和本地服务均继续复用。本轮新增模块为 `research/skill_study`，生产评级、路由及共享权重保持原行为。另按用户指示更新了本地演示的 DeepSeek 密钥并启动服务；密钥不进入研究材料、日志或 Git。

## 2. 阅读了什么，怎样避免凑论文数量

完整的 [44 篇逐篇学习表](LITERATURE_REVIEW.md) 给出标题、固定阅读版本、出版来源、优势、迁移限制与本课题用途；[机器可读文献账本](literature_review.json) 保存作者、正文指纹和阅读章节。

12 篇直接研究现代 Agent Skill；其余涉及程序技能、工具与 Agent、质量评价、证据、风险校准、集合选择和工作流优化。按已核验记录，35 篇有正式发表或会议录用信息，9 篇仅按预印本列入。正式来源包括 Nature、TMLR、Journal of the ACM、ICLR、NeurIPS、COLM、ACL/EMNLP、USENIX Security 等，不能将它们统称为“44 篇 Skill 顶刊”。SkillRouter 与 SkillLearnBench 的录用另在 [COLM 2026 官方名单](https://colm.eventhosts.cc/Conferences/2026/AcceptedPapers) 核实；阅读版本不冒充正式最终版。

这是一份围绕方法的定向综述，未声称穷尽所有文献、逐字通读每篇全文或完成系统性元分析。主要依据是论文原文、正式出版页面及作者发布版本，不以博客解释代替方法证据。

几个直接影响研究定位的结论：

- **多维评分、人工复核和沙箱验证已经存在。** SkillNet v3 已描述五维评价、200 例三位博士级标注者独立盲评，以及代码/工具调用的受控执行。因此，新增八维或增加一个 Judge 不能独自构成主要创新；本地旧启发式也不能冒充论文完整评价器。[SkillNet v3](https://arxiv.org/html/2603.04448v3)
- **真实效果要由独立产物判定。** 固定环境的有/无 Skill 对照可测收益，但上下文、答案泄漏和基准选择仍需控制。[SkillsBench v4](https://arxiv.org/html/2602.12670v4)
- **价值是任务条件化的。** 随机屏蔽能估计特定共存分布下的技能效应；不能把一个全局“好技能”标签替代每类任务收益。[ASSAY](https://arxiv.org/html/2606.15390v1)
- **多样性需要正确表示和相关性。** DSR 的 quality 指重排相关性，不是技能安全/可信度；其残差核和训练模型的效果不能由随意加一个去重项继承。[DSR](https://arxiv.org/html/2609.05824v1)
- **更新应检验忠实性与遗忘。** 元数据要能区分近邻且忠实正文，加入新技能后也要测旧查询。[Skill++](https://arxiv.org/html/2611.00544v1)
- **优化不是让模型自行宣布改好了。** 轨迹反馈、多个候选及工作流搜索可借鉴，但要接受独立验收和同预算对照。[GEPA](https://proceedings.iclr.cc/paper_files/paper/2026/hash/0e9e708b6f48e14fd0ac29e167413f76-Abstract-Conference.html)、[AFlow](https://arxiv.org/html/2410.10762v4)
- **最接近的新工作必须纳入强对照。** 10 月发布的 SkillCT 已包含九维、能力边界及基于参考画像的免执行估计；SkillLearnBench 已按技能质量、轨迹、任务结果分层。因此，这些框架本身也不能作为本研究首创。本研究需要检验目标包的反证/验收证据能否纠正相似画像预测与一致性代理的决策错误。[SkillCT](https://arxiv.org/html/2610.38147v1)、[SkillLearnBench](https://arxiv.org/html/2604.20087v1)

以上是借鉴依据。论文报道的提升不是本项目结果，组合这些机制也不自动成为新方法贡献。

## 3. Q1 的增强方案：从评分转向可反驳的能力声明

### 3.1 核验对象

固定一个完整包版本，把能力拆成原子条款：任务、输入模式/规模、输出及容差、依赖环境、权限/外部 I/O、预算/终止和排除条件。每条写明来源声明、审查员操作化或实际观测；不将未测范围推成可用能力。

每个条款保留五类状态：仅声明、静态支持、发现冲突、执行已验收、未知。若声称“这份 Skill 带来收益”，还必须另有有/无 Skill 对照。引用哈希和行号有效只证明可追踪，语义支持与实际产物仍要另外核验。

原八维 [评分锚点](../skill_assessment/RUBRIC.md) 保留，但质量分、风险门禁、条件适配和真实收益分开。unknown 为空值；安全与许可不能被其他高分抵消。纯咨询技能不因没有脚本而被判差。

### 3.2 借鉴后的具体增强

| 借鉴 | 在本项目中增加的约束 | 怎样检验增量 |
|---|---|---|
| FActScore / ALCE：原子事实与引用支持 | 每条能力承诺同时保存支持、反证和版本；引用坐标、语义、结论覆盖分开 | 真实但无关的引用、陈旧证据、关键承诺无支持 |
| SkillNet / G-Eval / Prometheus 2：rubric 评价 | 保留普通 Judge 强基线；同材料、同模型、同预算比较 | 八维人审误差与覆盖；旧方法只比较同构维度 |
| JudgeBench：客观正误对 | 真实包上的已知接口改动与无害变换，标准库参数解析作为强对照 | 缺陷检出、无害误报、未知比例与父 Skill 重采样 |
| SkillHEX / SWE-bench：失败假设和回归 | 修补前先给可反驳缺陷，修补后检查主任务及旧任务 | 原缺陷是否消失；是否新增失败或能力漂移 |
| AgentDojo / 恶意 Skill 实证 | 可疑静态线索、确认风险、正常功能分别评估 | 攻击目标与正常任务双指标，防止全拒绝获胜 |
| CRC / RCPS：风险校准 | 有独立校准标签后选择拒绝阈值，写明适用假设 | 错误放行—覆盖—人审成本；来源漂移另测 |

CRC 需要交换性、损失条件等；RCPS 的高概率风险控制也依赖抽样与校准条件。当前没有独立校准标签，来源又集中，所以本项目没有给出任何共形或分布无关安全保证。

### 3.3 经验能力边界

一个条件命中预检只能进入“适合尝试但未执行”。经验边界必须由模型、Agent、环境、预算及任务层共同定义，并给出独立任务数量、成功/失败、未运行与区间。范围外任务正确拒绝，与范围内产物成功分别计量。模型、环境、依赖或包版本改变后，旧证据需要重新检查。

### 3.4 最后怎样判“好、坏、能不能用”

不先给整个包盖一个永久的好坏章，而是对“这个版本、这个任务条件下的使用决定”作判断：

| 问题 | 决定依据 | 当前允许作出的决定 |
|---|---|---|
| 声明与包内实现是否一致？ | 明确接口、资源和实现的支持/反证 | 有冲突则退回修补；证据不足则保持未知 |
| 是否适合这次任务？ | 输入输出、依赖、权限、规模和预算前提 | 前提满足才进入受控试用；静态通过不授予能力认证 |
| 真的做成了吗？ | 与 Skill/Agent 分离的产物验收器；正常、边界和越界任务 | 仅对实际测过的条件登记成功率、失败类型和不确定性 |
| 值得加入网络吗？ | 相同 Agent/预算下有无该 Skill 的配对任务结果 | 有可重复净收益且满足风险约束，才支持该用途下采用 |
| 评价器本身可信吗？ | 独立人审、已知改动、无害变换、外部任务和强基线 | 分别报告效度、覆盖和成本；不能用测试通过数替代 |

例如，当前 senior-ml-engineer 的三个命令可以被明确判为“文档—接口不一致”，六个占位方法可以被判为“该方法体没有实现业务动作”。这两种反证足以阻止我们把对应示例标成已验证能力，却不足以证明整个包任何用途都无效。相反，一份文档写得完整、引用都定位成功的 Skill，也只能得到相应文档证据，不能自动获得“能完成任务”的标签。

可信度来自不同来源的测量相互约束：声明提供待证命题，静态检查提供机械反证，独立验收提供产物结果，配对实验提供因果收益证据，人审与外部分布评测检查测量失真。当前只有其中一部分落地，因而可以信任具体的可复查静态发现，尚不能说整体评价方法已具有高外部效度。“更权威”应由这些验证结果支持，不由引用顶刊数量、模型名气或多数票决定。

## 4. Q1 已运行的开发实验

### 4.1 数据与方法

只使用冻结 D1 的 200 个原始包：107 个来自 sickn33/agentic-awesome-skills，93 个来自 alirezarezvani/claude-skills。共 1,441 个登记文件、334 个 Python 文件。所有登记文件重新核对字节和 SHA；339 个非支持文本/二进制资源保留为不透明资源，不凭空宣称已分析。

从 Markdown 中提取本地 Python CLI 示例。仅支持明确的单一 argparse 解析器、字面选项、简单必填、choices、int/float/str 及布尔开关；动态构造、子解析器、位置参数等超出本轮范围时返回 unknown。绝不导入或执行社区脚本。

在静态一致且标准库重建参照也接受的命令中，每个父 Skill 按预设哈希顺序最多取 3 条，得到 35 个父 Skill 的 80 条命令。构造错误参数、遗漏必填、非法取值、类型错误，以及空白/等号形式等无害变换，共 381 例。

对照包括：只检查选项是否存在的基线、增加必填/取值/类型的检查、按白名单声明重建的标准库 argparse。标准库解析与自写约束逻辑不同，但**共享 AST 提取和词法预处理**，并非完全独立的端到端测量系统。已知干预定义也只覆盖这类机械契约，不是人类质量金标准。

### 4.2 全量检查分母

| 470 条真实文档命令观察 | 数量 | 解释 |
|---|---:|---|
| 在受支持范围内静态一致 | 134 | 未证明运行成功 |

这些结果说明：只检查“参数名存在”会漏掉某些明确的参数契约错误。它们不说明本方法以 100% 准确率评价所有 Skill。标准库强对照同样达到上述结果，所以这里的增益是补齐契约核验能力，不是超过成熟工具的新算法。案例来自 35 个父 Skill，不能把 381 例当成 381 个独立 Skill。按父 Skill 平均的检出差为 38.14 个百分点，条件 bootstrap 区间为 29.88–46.00 个百分点，仅描述当前选择的 D1 父包及构造缺陷。

### 4.4 真实发现和一次已纠正的误报

senior-ml-engineer 主文档第 283、291、299 行示例使用 `--model/--target`、`--analyze`、`--deploy` 等，而对应脚本字面解析器要求 `--input/--output`，并未声明这些选项。这是文档—接口冲突，尚未据此判整个 Skill 无法完成任何任务。[固定版本主文档](https://github.com/alirezarezvani/claude-skills/blob/19392f7a08264ed00486a251f5b2098321771f94/engineering-team/skills/senior-ml-engineer/SKILL.md)

复核这些例子后，另做了**事后探索**：在 D1 发现 senior-ml-engineer 与 senior-data-scientist 两个包的 6 个 `_execute` 方法，主体除说明外只返回字面 `{'success': True}`，邻近有实现占位注释。该方法主体没有完成所声明任务的业务逻辑；整个包是否有其他路径弥补尚未实测。这不是恶意判定。[固定版本示例脚本](https://github.com/alirezarezvani/claude-skills/blob/19392f7a08264ed00486a251f5b2098321771f94/engineering-team/skills/senior-ml-engineer/scripts/model_deployment_pipeline.py)

本轮初次扫描曾把行尾 `#` 解释文字当作参数，产生 11 条额外错误线索。修正引号/注释语义后，真实命令冲突从 14 条变为 3 条。初始数据与修正前源码均保留，[纠正记录](CORRECTIONS.md) 可查。这说明仅有规则、参照一致或可回放记录仍可能共同出错，必须有无害对照与语境复核。

### 4.5 DeepSeek 真实评价先导

用户在 2026-11-07 明确授权使用 DeepSeek，并提供替换凭证。本批次改为直连官方 API，未使用 OpenRouter 转发。初次只读检查发现旧凭证对应账户不可调用；替换凭证通过鉴权与余额检查后，才发送模型请求。这两种检查与 54 次评价分别记录，不把未调用状态写成模型失败。

使用原先冻结的 D1 训练 20 例，其中 2 例超过打包字节上限，实际纳入 18 个父 Skill。每例三臂使用同一材料：普通 rubric、支持证据优先、反证优先。每包最多 8 份文本，截取范围和遗漏均明示；不发送旧评分、人审标签或任务成功结果。三臂都增加相同 JSON 示例、简短理由/单条引用约束及来源许可声明，首臂位置按父包循环平衡。完整方案与逐次指纹已在首个请求前固定。

模型别名 `deepseek-flash`，官方文档当时标注 DeepSeek-V4.1-Flash-1017；关闭思考，温度 0，每次最多 2,048 输出 token，并发 1。API 返回的模型字段为 `deepseek-flash`，它是可变别名，不等同于固定权重版本。原提出的 $5 上限保留，另设独立的 ¥20 保守上限；缺用量、未知费用状态或连续三次不合格即停止，不自动重试。[授权与上限](results/deepseek-authorization.json)、[价格依据](results/deepseek-pricing-snapshot.json)

54 次全部返回，耗时约 286 秒；实际返回输入 501,675 token、输出 57,833 token。其中 53 次通过八维、状态—分值及字段结构检查；普通 rubric 有一次在“未知”状态同时给出数值，原响应保留为不合格，未擅自补成正确结果。[完整统计](results/deepseek-readiness-analysis.json)

| 提示方法 | 结构合格 / 请求 | 严格定位有效 / 引用 | 有效响应中的 unknown 维度 | 模型标成 conflict 的维度 |
|---|---:|---:|---:|---:|
| 普通 rubric | 17 / 18 | 123 / 125（98.40%） | 9 / 136 | 17 |
| 支持证据优先 | 18 / 18 | 132 / 135（97.78%） | 9 / 144 | 17 |
| 反证优先 | 18 / 18 | 127 / 129（98.45%） | 15 / 144 | 20 |

引用分母只来自结构合格的响应，不包括被拒绝响应中的引用。54 次请求来自 18 个训练父包，不能视作 54 个独立 Skill；两类来源也不能提供独立外部分布验证。引用更多由提示直接要求，conflict 更多、unknown 更多或分值更低均不自动代表方法更准确。这一小样本没有显示哪种提示在真实质量判定上获胜。

这三臂是同模型提示诊断，不是已发表 SkillNet、SkillCT 或 SkillLearnBench 评价流程的完整复现；正式效度实验仍须补上这些合理实现的强对照。

7 条未通过严格定位的引用逐一复核后，4 条属于未完整复制标注行的摘录，3 条引用了完整目录中存在、但未进入带编号输入正文的许可文件。因此，不能将这 7 条统称为虚构、将其比例当作模型幻觉率，或将它们当作 Skill 的 7 个质量缺陷。定位核验的 98.20% 也不是质量评价准确率。

按实际返回的用量和官方峰时、未缓存输入价，保守费用上界为 **¥1.466014**；按独立美元价口径为 **$0.2199021**，不是汇率换算。观察到账户余额下降 **¥0.25**，余额变化可能包含同账户其他活动，因此没有把它冒充逐次独立账单。完整用量、价格快照和预算日志保留，未公开账户总余额。[DeepSeek 官方价格](https://api-docs.deepseek.com/quick_start/pricing/)

### 4.6 根据先导结果补强：系统绑定来源，保留原始分歧

在上述结果之后新增了一个明确标为**事后工程诊断**的来源绑定器：只接受冻结包目录登记的路径，核对版本哈希和字节，按有上限的行区间由系统读取原文。模型不能指定任意本机路径；未登记、版本冲突、资源改变或不透明内容保留为未绑定。系统保留模型原始引用和四条摘录差异，不把替换后的原文倒算成模型原先正确。

389 条引用均取得了可核对的真实来源窗口：386 条来自已提供的编号文档，另 3 条由系统补取两个登记许可资源。额外取证的来源明确单列，不能说模型原先已经读过它们。**绑定器证明的是“这段来源存在且版本吻合”，语义支持和运行能力仍为未评估。** 这个结果不能写成“389 个质量判断全对”或新方法 100% 准确。[绑定结果](results/evidence-binding-summary.json)、[实现](bind_judge_evidence.py)

这把“模型给评分并声明依据”增强为“模型提出判断，系统独立绑定来源，语义和产物另验收”。它有直接可测的工程收益，但证据绑定/引用核验已有 ALCE 等前人工作；论文增量仍须通过独立语义人审、错误放行与真实效用实验检验。

## 5. Q2 的候选增强方案

单个 Skill 的评价应成为有条件的证据，而非全局静态加分。下一版网络选择研究将比较：

1. **候选召回与正文理解。** 复用现有 BM25/Hybrid/Fabric，比较卡片、正文与等长摘要，先测候选池是否含必要技能。未召回的能力无法由重排补回。
2. **可行性约束。** 按任务契约检查输入输出、状态、权限、依赖与预算；未知条件触发补充验证，不把 unknown 当作安全或零风险。
3. **任务条件化收益与集合互补。** 借鉴 ASSAY 的随机干预、DSR 的集合选择，使用实测的任务收益及交互证据；相关性只是召回信号。
4. **验证预算分配。** 借鉴 COBRA/上下文 bandit，把有限实跑分配给可能改变选择决策的高不确定候选，并与随机、只看高分、只看不确定性比较。
5. **局部修补与回归。** 借鉴 Skill++、GEPA、TextGrad、AFlow 和 SkillHEX；每次限定修改范围，保留多候选、证据、旧能力回归及可回滚版本。

候选目标可表示为：在作用域、权限、风险与总成本约束下，选择“经校准的任务收益下界 + 必要能力覆盖 − 成本”较好的集合与 DAG。收益下界不是任意 Judge 自信分；没有足够执行和校准数据时不得填值。

这是基于文献形成的**待验证组合方案**，不是已证明的新定理或首创方法。本轮只实现了六种固定参数的集合重排开发对照；条件收益模型、主动验证和可接受风险的正式校准尚未训练。不能把组合方案的设计优势当成已经获得的效果。

## 6. Q2 已运行的开发实验

使用此前冻结的 192 份检索捕获：两个库规模（76/1,881）、32 个既见任务、BM25/Hybrid/Fabric 三种模式。每份最多 20 个候选，固定选 5 个，运行原顺序、MMR、原核 DPP、两档查询残差 DPP和查询覆盖，共 1,152 条策略—任务记录。

选择器接口不接收参考标签，原顺序逐条复现。用固定词/汉字双字组 TF-IDF 和按检索名次推导的相关性，所有参数在实验计划中列明。它是 DSR 思路的词法代理，不是已发表编码器/重排器的复现。Fabric 捕获中只有图扩展，未做 LLM 重排。固定的是候选数预算，尚非同 token/费用的真实执行对照。

全部 12 个组别及所有方法见 [完整结果表](ROUTING_TABLES.md)，未只挑有利组别。下表展示全库 Fabric 这一组：

| 方法 | 基准 20：Recall@5 | 基准 20：完整参考集覆盖 | 既见 12：Recall@5 | 既见 12：完整参考集覆盖 |
|---|---:|---:|---:|---:|
| 原顺序 | 80.00% | 55.00% | 78.47% | 58.33% |
| MMR .7 | 80.00% | 55.00% | 75.69% | 50.00% |
| 原核 DPP | 80.00% | 55.00% | 78.47% | 58.33% |
| 查询残差 DPP .5 | 80.00% | 55.00% | 78.47% | 58.33% |
| 查询残差 DPP 1 | 80.00% | 55.00% | 78.47% | 58.33% |
| 查询覆盖 .5 | 80.83% | 55.00% | 78.47% | 50.00% |
| 候选池参考标签上限 | 100.00% | 100.00% | 94.44% | 91.67% |

可得到三项有限发现：

- 在本组开发数据上，多样性本身没有普遍增益；MMR 在既见 12 上下降，DPP 多数保持原结果。不能由此宣布 DSR 原论文无效，因为表示、模型和数据均不同。
- 查询覆盖使基准 20 的平均召回略增，却没有增加完整参考集覆盖；既见 12 的完整覆盖下降。平均召回改善不等于多技能任务需要的整组能力更齐备。
- 基准 20 的必要参考技能都在候选池中，而原前五的完整覆盖只有 55%，表明此组仍有选择空间。既见 12 的候选池也并非完整，召回瓶颈不能靠重排解决。

这不是新的独立留出评估：32 个任务此前已被使用。原文件名虽有 heldout，本报告称“既见 12”。同一任务在不同模式/库规模反复测量，不是 192 个独立任务。参考标签按技能名匹配，可能遗漏功能等价的社区 Skill，因此上述指标也不是能力真值或真实任务成功率。

必须保留同材料强基线和同总预算比较。旧卡片四个同构维度之外不能补零；原 safety 与安全说明质量不同。正式比较应包含公开方法的合理实现或明确标为适配版，不能只与本地弱启发式比较就宣称超越已有研究。

独立人类参照需要真实评审者：先 D1 训练、独立盲标，再由第三位有领域能力者仲裁，披露仲裁前一致性和未知比例。模型多数票不能替代人类金标准。校准、模型选择和阈值仅在开发材料完成，正式留出打开前冻结。

消融至少移除：完整资源、证据语义核对、未知/拒绝、条件收益、互补约束、主动验证与旧任务回归。分别衡量每一项的增量与成本，不能以全部模块合并后的提升推断每个模块有效。

另外做了[样本量敏感性计算](results/power-planning.json)。若配对结果不一致概率假定为 20%、双侧 α=0.05、每个独立任务族只贡献一个二元结果，100 个独立单位检测 3、5、10 个百分点提升的功效约为 6.7%、14.3%、54.4%；600 个单位检测 5 个百分点约为 76.0%。这是精确配对二项检验的假设规划，不是观测提升，也不直接适用于连续宏平均或人类序数评分。原有 100 个测试任务的规划未必足以检出小效应；需要先用开发试验估计不一致率和族内相关，再在正式留出打开前重新冻结样本量，不能靠重复调用把独立样本数放大。

## 9. 外部评测资源也已开始落实

没有只把“需要人工标签”列成后续空项。本轮已定位并按提交 `f7d28b1a9de4eb33d552529cf79d1065d765f6c3` 冻结 USENIX 安全论文所发布基准的元数据：98,380 条总体目录、157 条发布方标记的确认恶意记录，以及 README 和许可证文本；未获取或执行恶意源码。这 157 条是外部安全参照，不是本研究的通用质量人审标签。其余未确认条目不能一律充当良性金标准。[发布方基准](https://github.com/protectskills/MaliciousAgentSkillsBench)、[本地冻结摘要](results/external-security-metadata.json)

另外固定了 Hugging Face、Microsoft、Vercel、Expo 四个候选来源的版本与 270 条 SKILL.md 文件索引。随后对其中 Hugging Face 和 Expo 的 51 个候选原始文档及 292 个包资源做了盲冻结和词法近重检查；自动读取字节/文本计算指纹，没有让当前 Agent 或模型审阅这些正文。[候选来源索引](results/external-source-inventory.json)、[冻结与重叠摘要](results/external-pool-summary.json)

发现 5 个候选文档与既有内容簇连接：Hugging Face 3 个、Expo 2 个。虽然仍有 46 个仅含新文档的词法簇，但按照原方案“仓库来源 + 近重关系取连通分组”的严格规则，两个新仓库都会被连接到旧来源，仓库隔离的新来源候选为 **0**。因此，再找两个仓库没有自动修复外部独立性缺口。这是新增的来源审计发现，不能把 46 个新词法簇宣称为 46 个独立来源测试样本。

后续需要核实原始作者/上游来源链，或在正式试验前制定并冻结新的、论证充分的来源/时间划分，不能看测试成绩后选择切分。组件许可与语义近重仍待复核；Vercel 根许可元数据为空，也不能当许可通过。原 D2 没有被替换。

SkillLearnBench 的公开仓库已定位，可用于准备受控任务与验收；尚未运行。SkillCT 的正文已核对，但本轮尚未取得其完整评分表，不能声称复现其 4,098 个对象的实验。后续优先复用可取得的独立参照，再确定仍需组织哪些真实人审。

## 11. 论文定位与交付

候选研究标题为《面向开放技能网络的可证伪质量核验与任务条件化优化》。核心不是发明另一套技能格式，而是建立“具体能力承诺—可反驳证据—条件化效用—网络决策”的可检验联系。

潜在贡献有三项，均尚待正式验证：可回放且不强行补值的核验基准；经校准的证据如何预测适用和真实增益；在相同风险/成本约束下，验证与集合选择如何改善网络。当前两组开发实验和事后发现是基础证据，尚不是重大效果结论。
