# 从相关技能检索，走向有证据的能力边界

本轮完成了研究、真实子进程实验和产品接入。核心是“观察实际输入 → 定位未满足条件 → 执行定向实验 → 重新观测 → 独立验收”。它为用户给出的 Capability Frontier、可证伪技能和有限能力基提供一个可复验的工程起点，尚未建立学习得到的因果世界模型。

## 方法与可复现范围

研究依据、原论文方法与边界见 [frontier-research.md](frontier-research.md)。实现采用有限事实、requires/adds/deletes 算子和 Dijkstra 搜索，保留成本/深度 Pareto 标签。只有完整穷尽声明状态空间才返回声明模型内不可达；搜索截断返回 unknown。路径存在也只证明声明兼容，真实产物仍须执行检验。

清洗动作会保守地撤销 nonempty/range/binary 等事实，防止把筛选后的未知性质当成保持不变。控制器按已公开的固定清洗优先次序执行能补充缺失条件的动作，然后回读真实输出再规划。这是固定策略的定向执行和重观测，**没有训练策略，也没有学习成功概率**。

任务语义在执行前冻结：按 sample_id 保留首条、移除全部跨 split 的 subject、只删除空白 score；保留其它原始单元格和顺序；只在 test 留出集按 `>=0.5` 计算指标。独立 oracle 不导入执行器源码或规划器预测。NaN、越界和非法标签不做任意修复。

16 个有效任务包含 8 种三类缺陷的组合，以及名字、行序、数值拼写和额外阈值样本不同的 8 个留出输入变体。另有 7 个负例。留出变体属于同一合成任务族，不是新领域或真实科研数据。每个任务各策略调用上限相同为 5，不把上限相同说成实际成本相同。

## 最终冻结实验

最终完整报告 [frontier-lab.json](evidence/frontier-lab.json)，执行前协议 [frontier-protocol.json](evidence/frontier-protocol.json)。完整报告的 canonical SHA-256（排除自身摘要字段）是 `24a40ed1a75075a47cf99d4d3882828915946a1b0b43df8561e320d3f82f0704`；协议是 `940244b6a5fe436148d3bd33c0d1c9ae3d866a3d40511d8b0154797f558b77c6`。这些不是 JSON 文件原始字节哈希。

| 相同任务族与调用上限 | 有效任务独立通过 | 负例被误接受 | 实际 Python 调用 | 生成了未通过复核的指标 |
|---|---:|---:|---:|---:|
| 直接执行检索候选 | 2/16 | 0/7 | 23 | 7 |
| 仅声明模型规划 | 2/16 | 0/7 | 3 | 0 |
| 定向执行并重观测 | 16/16 | 0/7 | 42 | 0 |

三组都使用独立 oracle，所以没有一组把错误中间指标当成合格交付。本轮支持的收益是**在这个冻结任务族上提高可完成覆盖**，代价是更多真实调用；不是省成本，也不是通用技能检索精度提升。

此外实测了：

- **同题补能力**：移除唯一的跨分组排除程序会阻断；恢复该提供者后，同一输入 SHA 的任务通过独立验收。节点增加本身不计为成功。
- **反例拒绝版本**：`>=0.5` 与 `>0.5` 的声明相同，结构检查无法区分；独立阈值算术揭穿缺陷版本。只在当前实验调用内隔离该代码指纹，不归罪上游有效技能，不奖励所有参与者。
- **主动探针**：两个预定义确定性比较器假设、三个候选输入，按预测分歧熵排序。主动顺序首次反例 1 次调用、固定顺序 3 次、20 个随机次序平均 2.1 次。22 个次序均真实运行，总计 46 次调用；选择程序没有读取隐藏输出或 oracle。这是构造的小假设集，不代表开放任务最优实验设计。
- **有限能力基**：实际测试全部 32 个登记子集 × 8 个冻结开发任务，保持 8 题实测覆盖所需的最小规模为 4，分别为三种清洗及正确指标程序。这只是在本控制器、目标集合与环境下的最小登记子集，不是 1881 个文档技能的全局最小能力基。
- **保留模型失配**：数据结构和数值都合规但没有 test 行时，声明路径存在，执行仍失败。这暴露契约缺少留出集条件；失败不被包装为能力提升。

最终矩阵共真实启动 **391 次 Python 子进程**。报告保留实际源码、输入、输出文本、退出状态、前后事实和 SHA。329 份运行报告及 46 条探针记录通过独立重建与算术复核。四个公开 scenario 的执行记录缺少独立开始时间戳，因此没有宣称它们各自的开始时间也已核验；其它带时间戳记录均核对协议先于执行。

初版完整矩阵也执行了 391 次，其 CSV 文本预览因 text-mode 读取丢失 CRLF，不能与记录的原始字节 SHA 对齐。初版完整报告保留在 [frontier-initial.json.gz](evidence/frontier-initial.json.gz)，原因和修复见 [frontier-serialization-issue.json](evidence/frontier-serialization-issue.json)。修复后完整复跑的数值结果相同；两轮不是独立样本，不能把任务数翻倍。

## 进入当前项目的部分

- 全部六个页面共享“能力边界实验”入口。五个公开情景可以现场真实执行；展示条件缺口、实际状态变化、独立复算和失败，不需要模型额度。
- 原有自检索、球体技能网络、七阶段回放和背景保留。首页新增本轮真实提问回放，方案阶段显示输入观测与有限缺口，完整结果中可核对证据。
- 生产科研任务增加**只读桥接**：精确宿主任务、输入登记 SHA 与实际文件必须一致才记录 `capability.frontier`。普通问答没有该字段；不把五个实验执行器等同于整个文档技能库。
- 原有 Run、证据胶囊和能力报告携带这份执行前观察；后读时重新核对原始输入完整性。没有反填旧记录。实验执行不替代原生产计划、独立评价或十二道 AND 奖励门。
- API 只接受固定 scenario_id，不接受代码、路径或任务数据。令牌、S1 后端身份签名、防重放、两个并发名额、有界子进程和临时目录清理均有回归覆盖。轻量报告接口先核验完整报告，再返回约 12KB 的投影，完整证据独立下载。
