# 任务驱动的技能自检索与整页呈现复核

2026-10-10。本轮把“为问题选出有用的几个 Skill”放回主线，再连接真实交付、独立核验与经验积累。它们共同构成面向 S1 的科研能力生态。

## 查到的问题与修正

1. **筛选后仍补足数量。** 原模型重排提示词要求“只保留真正需要的技能”，代码却把未选候选追加回推荐集。现在有效选择允许少于 k 项；显式空选保留为空。调用失败、格式错误和未知技能仍走可观测降级，不能伪装成成功拒选。
2. **候选池前后不一致。** 实时运行完成检索后，编排又进行一次检索。现在复用已保存候选的前 20 项，编排可从中补齐必要协作能力，并保存实际读过的候选名。检索推荐不等于最终采用。
3. **选择依据藏在折叠表格。** 新增显式检索漏斗、能力卡、采用理由、声明交付物与实际动作，全部候选及未采用理由仍可展开。区分推荐、编排采用、进入步骤、通用执行；不把 manual 计成技能，也不事后编造历史理由。
4. **S1 交接遗漏检索依据。** evidence-v1 增加只读 `routing` 投影：记录推荐/采用/进入执行、通用步骤、候选、模型理由、编码器及降级状态。它只读取运行时事实，不读取当前技能库来补写历史。
5. **首屏与后续章节断裂。** 背景原来只在 hero；后续章节混用白卡、蓝灰表格和绿底结果层。新增仅作用于首页的 `presentation.css`，使用贯穿全页的固定流动背景、墨色半透明表面、统一的青绿/暖金色、章节留白与表格样式。原始图片、星图、七阶段和会话交互保留；旧版备用 stylesheet 保留原文件。
6. **下方说明落后于实际治理。** 校正“模型评分直接写回正式排序”等旧文案；机制响应不再写成质量提升，也不将早期种子库阈值声称为扩容后已重新标定。

这些结果证明本轮行为及产物范围，**没有证明全库最优组合、总体准确率、技能的因果贡献或网络增益**。必要性筛选与编排理由仍是模型建议；实际参与和可交付性由执行事实支持，提升奖励仍受独立对照及十二门限制。`policy_check_scope` 说明参数指纹检查覆盖新运行还是只读复核。

## 验证与边界

- 326 项 pytest 通过；31/31 交付自检通过；五组 Node 检查通过。新增回归覆盖短选、显式空选、异常降级、候选复用、通用执行区分和 S1 路由证据的只读投影。
- 首页新增章节锚点与横向表格容器；窄屏卡片改为单列，保留键盘焦点及减少动态效果设置。前端检查验证流程与转义，不能代替视觉验收。
- 浏览器工具因 Windows 沙箱初始化错误无法启动，**本轮未完成真实滚动、点击与截图验收**。当前保持 Draft PR，不能声称视觉效果已由截图确认。
- 扩容后的任务分流阈值尚未完成重新标定；社区技能导入不等于执行认证。S1 线上联调与跨任务增益仍待验证。
- 跨平台 CI 曾发现无语义模型时少量候选会跳过必要性筛选；现已取消“候选数 ≤ k 就跳过”的旧条件，单元回归固定使用词法回退环境。少量候选同样必须支持短选与拒选。

## 生态依据

[Agent Skills 规范](https://agentskills.io/specification) 通过描述说明能力及适用条件，并按需加载正文和资源；本项目在检索卡中保留能力、适用条件及交付物，以支持任务选择。[SkillNet 上游](https://github.com/zjunlp/SkillNet) 已提供技能发现、关系分析与任务路由研究，构成设计参考。本项目的价值判断落在如何把检索、执行、结果证据和候选治理一起服务 S1，而不是独创性声明。
