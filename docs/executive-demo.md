# 一次提问，展开整个内核

首页保留原有流动墨色背景、可探索技能星图、完整七阶段演示与实验对照。新的主舞台直接位于首屏之后，提问与执行过程在同一个视图中展开。

## 建议现场操作

1. 打开首页，先展示真实技能网络；每个节点对应当前库中的技能。
2. 先点击「回放一次真实任务」与「汇报模式」，完整展示本轮三步经营月报；现场提问可选「经营月报 · 数据到决策」再启动能力网络。
3. 沿左侧阶段说明：找到哪些能力，历史经验如何参与排序，技能依赖如何进入实际执行 DAG，代码如何运行，失败如何修复，产物如何验收，经验是否回流或准入。
4. 点击阶段查看实际值；点击节点先核对实际文件版本、SHA-256 和服务端检查，再展开代码、模型复核与修复记录。图中的步骤编号独立于技能名，同一技能重复用于不同步骤也能区分。
5. 结束后展示七项内核贡献、直接回答与文件预览。下载文件可以按 SHA-256 核对；后续步骤修改同名文件时，以不同步骤的产物记录保留版本。
6. 点击「沿用同一文件追问 · 原值已核验」展示已完成的在线追问与逐格检查；也可继续实际提问，携带前文和真实文件。刷新页面后仍恢复同一个运行，不额外发起任务。

现场网络或模型延迟不稳定时，可选择「真实记录回放」。它读取仓库中的公开数据运行记录，支持暂停、1×/4×/8×与时间轴定位。回放明确标注，既不调用模型，也不更新技能库。

## 各阶段展示什么

| 内核 | 前端证据 | 解释给领导的价值 |
|---|---|---|
| BM25 / Hybrid / Fabric | 同题各档候选、实际启用组件、降级状态 | 能追查能力从哪里来、是否存在漏选 |
| Shared LinUCB | 收益预测、探索项、实际优先级 | 反馈能影响下一次选择，仍保留探索机会 |
| Wiki / 关系编排 | 采用技能、编排边、来源与降级 | 明确协作关系与依赖 |
| 规划与 Runtime DAG | 实际步骤、执行状态、步骤依赖 | 方案进入真实执行语义 |
| Python / 自动修复 | 生成代码、运行输出、尝试与错误 | 获得真实文件，同时保留失败和修复轨迹 |
| 分层验收 / 方案评审 | 程序检查与语义验收，独立方案评分 | 完成、合格、评审不可用分别可见 |
| 反馈与进化 | 实际反馈、候选隔离、冻结配对与晋级结果 | 没有提升的候选不会污染能力库 |

排序首位不一定被编排采用；规划采用的技能数与实际执行关联的技能数可能不同。相关度为启发式指标，不是任务成功概率。价值说明解释机制，不声称未做对照实测的提速或节省比例。

## 验证与边界

- 228 项 pytest、31 项自检通过；新增回归覆盖输入 CSV 观察值、不可变文件原值检查、跨轮引用、实际代码/输出、修复与候选晋级门。
- 前端检查覆盖事件去重、阶段顺序、部分完成/取消、真实记录回放、DAG 布局与 CSV 安全预览；原有七阶段仍完整保留。
- 本轮业务运行、在线追问、Docker 与学习配对证据见 [升级说明](scale-upgrade.md)。四组学习前后分数均为 1.0，没有测出增益，候选未晋级。
- S1 生产联调仍待真实后端接口、身份和环境配置；Linux Docker 实机验证通过。本机默认宿主子进程仅适合受控演示。

实时数据会随真实运行变化。已有实验与旧运行记录保留各自的时间和结果，不能把历史回放当成当前重新执行的结果。
