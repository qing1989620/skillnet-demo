# 十二道门全部通过，才给提升奖励

任务完成不等于技能提升。新版本只有在公平的真实对照中优于原版本、且所有硬性约束满足时，才获得提升积分。模型评分不进入奖励公式，不允许用高分抵消任何一道失败的门。

## 后端执行的规则

规则定义在 `skillnet/reward_gates.py`。十二道门采用 AND；状态只有 `passed / failed / unknown`，后两种均阻止领奖。执行前的评价契约记录规则 SHA-256；完整对照计划进一步冻结奖励阈值、候选与基线版本、候选来源记录、已知训练任务谱系、题目参考、模型、代码、预算与运行顺序。规则或证据改变后必须重新评测，不能事后修改阈值让候选通过。

| 门 | 必须满足的条件 |
|---|---|
| 01 标准提前冻结 | 物理评测计划的指纹正确，当前规则、代码与参考匹配，实际运行晚于登记 |
| 02 独立重算结果 | 重新读取真实产物，独立算术结果与报告一致；候选所有独立约束全部通过 |
| 03 物理产物可信 | 文件存在、路径合法、登记和步骤指纹一致，无重复登记 |
| 04 执行完整合格 | 候选动作与依赖完整、必要验收通过，无取消、删步和成本/调用/时间超限 |
| 05 绑定技能版本 | 两组实际使用冻结的精确版本；当前基线未变，候选不能冒充基线 |
| 06 对照条件公平 | 同模型、同预算、同执行模式、同动作依赖，按计划交替前后顺序 |
| 07 任务未用于生成 | 排除来源运行、已记录祖先和当前训练任务，谱系与登记快照一致 |
| 08 完整报告样本 | 至少 5 道不同留出任务各 2 组配对；完整覆盖，不漏报、不复用运行 |
| 09 每组没有退步 | 每组候选独立得分 ≥ 原版本；其他题的大幅提升不能抵消退步 |
| 10 增益达到门槛 | 不同任务等权的平均增益 ≥ 0.02 |
| 11 多任务一致提升 | 按不同任务而非重复运行计算单侧符号检验，p ≤ 0.05 |
| 12 同一版本只奖一次 | 同版本没有奖励凭证、同名技能不存在，不覆盖旧版本，也不分奖给其他技能 |

审计返回所有门的状态、原因、结构化证据和审计指纹。没有对照的单次任务最多证明前四项，后续门保留未知；这不是负面评价用户的任务。

## 全部通过后实际发生什么

`tools/promote_candidate.py` 重新审计物理证据，全部通过才执行晋级。只给被测候选版本写入：

```
提升积分 = min(25, 100 × 不同任务等权平均增益)
```

这是有上限的版本提升积分，不是成功概率、因果效应估计或全网收益。现有评测中整个工作流统一替换为候选版本，因此只能支持该版本在这套工作流中的相对表现，不能拆成各步骤的贡献。模型评分、调用次数、其他参与技能不会分享积分。

积分保存在 `skill.stats.verified_improvement_points`；同一原子技能库快照保存 `verified_improvement_receipt`，包含版本、计划、规则、审计与报告指纹、范围和积分。保存失败回滚内存。候选文件的晋级标记是次级记录；即使次级写入中断，技能库凭证也能拦截再次领奖。晋级前需停止 API 写服务和独立 worker，晋级后重启使新版本可见。CLI 与运行服务共用写锁，并在加载技能库前获取独占写锁，避免两个晋级进程使用旧快照同时写入；崩溃残留锁需检查原进程后处理。当前不提供在线写奖励接口。

积分和版本凭证可在技能库、星图详情和候选 API 查验。十二门面板在首页演示、对话、任务详情和运行中心共用；终态再次同步成本和取消事实。原七阶段流程、背景、星图和历史回放保留。旧记录没有补写新版通过结论。

正式 LinUCB 参数部署仍需独立策略验证。候选在固定业务题里获奖，只支持这一范围，不能证明通用检索策略已变好。五题、重复次数、阈值与符号检验是保守发布规则；题目代表性、相似任务的相关性、报告洞察、用户满意度和模型外部预训练内容仍有局限，增加门的数量不能消除这些局限。

## 真实任务核验

2026-10-10 三次付费 HTTP 运行共 ¥0.4817：

| 实际运行 | 结果证据 | 十二门结论 |
|---|---|---|
| `b5492bb7-20261010-083955-a445` | 经营月报独立重算 23/23；完整执行 | 4/12 通过；缺少提升对照，0 积分 |
| `1624c869-20261010-084055-eeaf` | 主观建议文件生成；没有独立标准答案 | 3/12 通过；结果判据及对照未知，0 积分 |
| `b5492bb7-20261010-083743-1b37` | 模型自拟的月度负毛利断言错误，重试后仍部分失败 | 2/12 通过；执行与结果约束失败，0 积分 |

两次经营任务的模型评分均为 9.0/10，实际结果却分别完成与失败；高分不能替代产物和执行证据。正式策略参数指纹前后一致。原始报告见 [真实十二门实测](../out/reward-gates-smoke.json)，文件校验见 [证据清单](evidence/reward-gates-files.json)。没有把正常完成冒充为跨任务提升。全部通过后的正向领奖路径由真实文件、二十份确定性运行夹具覆盖，明确不作为业务提升证据。

## 复核命令

```powershell
# 只读审计：列出全部十二门；不调用模型、不发奖。被拦截时退出码 2。
python tools/promote_candidate.py CANDIDATE.json REPORT.json --audit-only

# 执行前冻结的完整真实对照；至少 20 次运行，调用已配置的付费模型。
python tools/benchmark_execution.py --candidate CANDIDATE.json --repeats 2

# 全部门通过才晋级，并写入该版本的唯一奖励凭证。
python tools/promote_candidate.py CANDIDATE.json REPORT.json

# 重查已交付证据，不再调用模型。
python tools/reward_gates_smoke.py --business-run b5492bb7-20261010-083955-a445 --unmeasured-run 1624c869-20261010-084055-eeaf --failed-run b5492bb7-20261010-083743-1b37
```

受令牌保护的 `GET /api/learning/reward-policy` 可核验当前规则与指纹。正向领奖、每道门未知/失败的阻断、泄漏、回放、篡改、删步、超预算、落盘失败与重启持久化均有确定性测试。本轮浏览器工具因本机 sandbox 初始化错误不可用，未完成截图视觉验收。
