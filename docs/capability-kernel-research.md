# 从研究主张到可执行内核

审查日期：2026-10-12。本轮重新阅读了用户给出的长文和长图，并核对下列论文的方法章节。结论是：球体网络适合展示能力生态，但“Skill 由它产生的状态变化定义”必须落实到执行路径，不能靠增加状态卡片完成。

## 论文实际给了什么启发

| 一手来源与已读部分 | 核验后的方法要点 | 本项目应采纳的内容与边界 |
|---|---|---|
| [Contract2Tool，IV、V、IX](https://arxiv.org/html/2606.07904v1) | 从文档与执行前后状态生成 requires/produces；按预定义状态词表正规化、校验；实验使用受控工具和主要成功轨迹。 | 使用明确且可计算的谓词词表。声明的 effect 只是预测，必须从产物另行观测；这不是自动获得任意科研任务的因果模型。 |
| [SIGIL，2、3](https://arxiv.org/html/2607.27309v3) | 区分模型语义判断、可执行操作、控制流；类型化读写、来源跨度、绑定与路径约束经验证后确定性降低为 harness。论文明确结构正确不保证来源解释正确。 | 将前置条件放在 code generation 之前强制执行；失败时不存在继续执行的路径。仍允许模型写分析代码，不把文字提示冒充控制流。 |
| [ASSAY，2、Appendix K](https://arxiv.org/html/2606.15390v1) | 在留出任务中随机独立遮蔽技能，用包含/不包含的结果均值差估计条件贡献；小样本单格归因噪声较大，按模型分别测量。 | 产物通过只算本次观察，不给所有参与技能发奖。后续效用学习必须有干预、模型和任务范围；执行门禁实验也不能冒充技能的因果贡献实验。 |
| [ReuseRL，3.1–3.7](https://arxiv.org/html/2605.31509v2) | 把轨迹投影到环境相关的原子字母表，用共享短序列字典和动态规划分段衡量描述长度。界限针对固定策略下未来成功序列的描述长度。 | 先明确本任务族的可执行 primitive，再考虑组合覆盖与冗余。论文不证明任意智能体的最小能力生成集；本项目也不能把少量算子直接命名为普遍最小技能基。 |
| [PolySkill，3.2–3.3](https://arxiv.org/html/2510.15863v2) | 用领域抽象类定义目标签名，各网站提供具体实现；新技能经重跑验证后纳入。 | 将能力签名与实现版本分开；用同一组输入探针比较真实输出。有限探针一致只是可撤销的观测等价，不是所有环境中的行为等价证明。 |
| [SkillHEX，3](https://arxiv.org/html/2608.05628v1) | 失败假设转成可执行测试，在证据库上复验，再指导保留多个修订分支的搜索。 | 反例必须保存输入、代码版本、实际输出和独立判据，不能只保存“模型认为失败”的解释。 |

这些工作共同支持一条工程路线：**可计算契约 → 执行准入 → 真实产物观测 → 主动反例 → 有范围的能力证据**。这是对用户研究构思的有界落地，不是声称已经完成 Skill Dynamics 的全部理论。

## 审查发现的原有内核缺口

1. `capabilities.passport` 只有声明字段，不能阻止不适用技能执行；`transitions` 是执行后证据投影，不能决定下一步。
2. `pipeline.run_step` 原先在生成代码前主要携带文件名；缺失输入和数据约束往往到执行后的检查才失败。提示“禁止重造数据”不能替代硬性准入。
3. `build_steps` 根据文件名和技能边推断依赖，不能推导下游所需数据性质；上游输出 CSV 不等于输出了“无缺失、唯一、无泄漏”的 CSV。
4. 现有独立科研参考对固定清洗与指标任务有真实算术判据，但单次通过仍不测可迁移范围，更不能识别两个实现是否行为一致。
5. 现有 12 道奖励门已阻止把一次成功当作改进。新状态契约应增强执行正确性，不能绕过留出对照和版本门禁。

## 本轮应建立的内核语义

状态事实绑定到 `artifact SHA-256 + predicate version + spec`，不绑定到含糊的文字名称。每个条件返回 `passed / failed / unknown`：实际反例为 failed；未支持条件、不可读取或尚不存在的未来文件为 unknown。只在全部前置条件通过时放行声明要求的执行；没有类型化声明的历史与通用技能仍须明确标为未认证，不能一概宣布全库无能力。

规划阶段只能验证**声明兼容性**，执行阶段才观测真实状态。上游声明 `ensures` 不得直接变成已观测事实；下游读取上游文件时重新核验。前置条件阻断应发生在首个执行器 LLM 调用之前，并保存事件、失败条件和零次代码调用证据。后置条件失败进入修复，修复后的文件必须重新完整检查。

CSV 首批词表可包括表头、非空、必填列、组合键唯一、有限数值范围、枚举集合、实体跨 split 互斥。这里每一个条件都能由真实字节反驳，且能解释不适用原因。二分类标签使用 `csv_values_in([0,1])`：数值在 [0,1] 内不能排除 0.5，范围检查不能冒充二分类约束。默认不自动从问题猜业务阈值：清洗策略、阈值与单位必须来自明确任务声明或可信版本化契约。

能力边界需区分三种结论：当前有限算子集合内没有可达组合；当前检索候选缺少提供者；证据不足无法判断。只有第一种能在明确的闭世界和深度界限内称为不可达；后两种不能变成“智能体不会”。若增添新算子，应该能在同一输入上演示可达集合扩大，而非仅增加节点数。

## 必须执行的实验，而非只跑规则单测

`tools/capability_probe_lab.py` 的设计是固定、已审查的三个 Python 实现，分别真实启动子进程读取输入并写结果：两个不同实现，以及仅把 `>=` 改成 `>` 的文本近似错误实现。先冻结输入、谓词、独立 Decimal 算术参考、代码指纹、随机种子及双策略次序；再用正常、阈值边界、缺失、重复、越界、表头漂移、跨集合泄漏、NaN、0.5 非法标签、空表和未支持约束这 11 个探针运行。

两种策略使用完全相同的实现：基线全部执行；契约策略仅在所有真实前置条件通过时执行。比较错误产物放行、有效任务误阻断、unknown、实际子进程调用数和独立结果判据。有限行为签名只纳入共同已执行的有效探针，阻断不能算作两个实现行为一致。正确契约也不能修复 `>` 的业务 bug：边界输出仍必须被独立 oracle 拒绝。实验不会更新正式技能库或奖励。

已运行结果保存在 [完整协议与逐次证据](evidence/capability-probes.json)。不是预测值：执行器实际启动了 39 次 Python 子进程。

| 指标 | 不设准入的同一批实现 | 使用真实产物谓词准入 |
|---|---:|---:|
| 预注册 probe × 实现 | 33 | 33 |
| 实际代码调用 | 33 | 6 |
| 违规输入仍执行 | 24 | 0 |
| 违规输入仍生成指标文件 | 15 | 0 |
| 有效任务误阻断 | 0 / 6 | 0 / 6 |
| 证据不足而阻断 | 0 | 3 |
| 有效任务的独立正确输出 | 5 / 6 | 5 / 6 |
| 结构检查通过、业务结果错误 | 1 | 1 |

最后一行非常关键：门禁避免了不适用输入的执行，但没有把有 bug 的实现变正确。错误比较符在阈值恰好 0.5 时被真实产物反例推翻。两个不同正确实现只在这次两个共同有效探针上同签名；证据不会自动合并它们，更不会宣称普遍行为等价。

## 容易自欺的反例

- 全部空表使“所有数值合法、没有重复”真空成立，必须另有非空条件。
- NaN、Infinity 不能作为范围内数值；晚于采样窗口的坏行不能被漏掉。
- 模型把错误的列名、单位或清洗规则写进契约，规则再严也可能执行错误业务意图。
- 数值范围通过不证明混淆矩阵正确；结构验收与业务 oracle 必须分离。
- 超过观测上限是 unknown，不能悄悄抽样后宣布全文件通过。
- 同名但不同指纹文件、不同模型和不同技能版本不得共享认证结论。
- 两个实现只在两个 probe 相同，不代表所有输入行为等价；新反例应能拆分该组。
- 缺少当前候选提供者，不代表千余技能或基础模型没有这个能力。

领导演示应从一个真实问题展开：系统为何选这些技能、哪些条件满足、哪条条件阻断、哪份真实文件改变状态、哪个反例推翻了宽泛承诺、为何这次仍不给奖励。球体用于定位这些能力和边界，核心说服力来自这条可重复的执行链。
