# 提问产生经验，证据决定是否值得学习

后续迭代：[十二道门全部通过才给予提升奖励](reward-gates.md)。下文保留 10 月 9 日的机制与原始实测，单次观察不会自动变成提升积分。

一次提问没有资格直接优化整个技能网络。它最多产生一条有选择偏差的执行轨迹：不知道换一个技能会怎样，也不知道这次成功来自技能、模型、输入简单或偶然性。**结果正确、某技能有因果贡献、网络整体变好，必须分别证明。**

旧实现存在实质缺陷：通过执行检查后，把方案的模型评分除以 10，作为所有已执行技能的共同奖励，立即更新共享 LinUCB 参数。它把方案质量、产物质量和技能贡献混为一谈，而且一次标量更新会影响未执行技能。本轮已移除真实任务与旧七阶段演示中的这条直接更新路径；保留原有页面、背景、星图、执行与回放。

## 好与坏，针对哪个命题？

| 命题 | 可以使用的证据 | 不能据此推断 |
|---|---|---|
| 代码是否完成、文件是否存在 | 运行状态、必要检查、实际文件 | 用户目标是否满足 |
| 数字是否正确 | 执行前冻结的数据与独立算术，重新读取实际 CSV | 报告洞察是否有价值 |
| 文件转换是否符合指定契约 | 不可变输入、原值投影、排序与精度重算 | 模型生成的契约必然符合用户意图 |
| 用户是否满意 | 用户明确审阅；本轮未采集时保持未确认 | 满意一次意味着跨任务更强 |
| 技能是否带来增益 | 同题同预算、候选版本绑定的真实对照 | 单次成功就是技能的因果贡献 |
| 网络是否整体提升 | 代表性任务分布、独立留出评测及部署后验证 | 某个经营任务套件的通过率能代表所有领域 |

因此，服务返回 `scope_verdict=passed/failed/unknown`，只描述已测范围；`overall_verdict=unconfirmed` 保留整体目标与满意度的判断边界。文件丢失、指纹不一致或参考不可用，表示证据不可信，保持未知；不是给用户结果判坏。模型语义复核仍供审查和修复使用，不能独自充当学习奖励。

模型裁判可能存在位置、长度与自我偏好等偏差，相关研究支持将其作为有限的近似信号，而非真值。[Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)。本文采用“独立结果判据优先、无判据则弃权”的工程选择；研究没有为本项目的具体阈值提供认证。

## 已实现的链路

1. **执行前锁定评价契约。** 精确匹配冻结业务题，绑定任务、数据、规则、参考实现版本与 SHA-256。仅规范化问题首尾空白，与 HTTP 入参保持一致；不做模糊匹配。一般用户问题没有独立标准答案时明确记录，不能让模型事后编出标准答案。事件 `evaluation.prepared` 早于执行 DAG。
2. **执行后重新核验证据。** 检查登记文件是否在产物目录、实际 SHA-256 是否一致。独立业务 oracle 重算月份、收入、成本、订单数、毛利及毛利率；SVG 存在与模拟数据标记只是最低交付要求，不能评价图表设计或报告洞察。
3. **限定步骤观察。** 只有实际生产月度汇总文件的步骤获得该表数值范围的观察。清洗、绘图与报告不会分享它的分数。上游失败导致的跳过不归罪下游；没有结果判据的步骤不分配奖励。观察仍只是关联，未声称因果归因。
4. **影子预演。** 在参数副本上预演，单次轨迹总权重最多 0.25，多步骤不会放大奖励。正式 A、b、更新次数、技能奖励统计均不变。`GET /api/learning/policy` 提供受访问令牌保护的状态指纹，便于外部核验。0.25 是预演约束，不是校准后的可信度。
5. **隔离候选。** 独立范围通过、全部步骤必要检查与语义要求通过、无遗漏时，可以蒸馏待验证的方法；记录证据范围、来源运行、当前问题、历史问题、跨轮输入及已知父技能来源的任务指纹。候选不会加入正式库，也不会改变图关系或排序权重。
6. **晋级必须另证。** 执行前保存不可变评测计划：候选与正式基线的名称/内容指纹、完整题目与参考指纹、重复次数、预算、模型、沙箱和执行源文件版本。至少 5 道排除已记录训练来源的留出任务，每题至少 2 组配对；两次重复交替先后顺序。拒绝遗漏、重复、挑选结果、事后注册、基线偷换或版本变化、预算差异、训练题泄漏、文件篡改和虚报分数。服务端重新核验全部物理运行和产物；基线必须仍与当前正式库一致。

晋级分数政策：任一配对不允许回退；按不同任务先聚合重复结果，任务平均增益至少 0.02，单侧符号检验 p ≤ 0.05。同一道题跑 20 次仍是一道题。阈值是本项目的保守发布政策，不是通用能力保证；相近经营题之间仍可能相关，p 值也不等于“成功概率”或普适的因果证明。多次筛选候选还可能产生多重比较偏差，不能不断试到达标后声称置信保证。

当前新增四个冻结经营变体，涵盖零收入、精度、冲突重复、跨年与非连续月份；连同原两题共六题。它们只形成经营数据管线的有限测试范围。新候选尚未跑完这个增强套件，不能宣称已晋级或跨任务增益。已有四组旧评测均为 1.0 → 1.0，继续保持零增益、拒绝晋级的结论。

手动 `/api/evolve` 仍可生成方法提案，但明确标注 `unexecuted_proposal` 与 `plan_advisory`；规划轨迹不再伪装为成功执行或实测分数。没有来源运行的提案不能通过正式晋级门。

**当前正式排序参数从零开始，真实请求不会部署学习后的参数。** LinUCB 数学更新能力仍用于离线实验与影子观察，不能把可运行的算法等同于已验证的生产学习系统。候选即便通过晋级，只改变经过验证的技能目录；排序模型部署还需要独立策略评估与发布流程，本轮没有声称实现这一步。

本项目没有记录随机曝光概率，也没有实现 IPS/反事实因果估计；因此不会把普通排序日志伪装为反事实证据。确定性日志的反事实学习需要额外方法与条件，不能靠一句“历史反馈有效”略过。[Counterfactual Learning under Deterministic Logging](https://aclanthology.org/D17-1272/)。外部模型的预训练集也不可核验；“留出”只针对本项目记录的候选生成来源。

## 两次真实模型调用链的反例

| 运行 | 方案模型评分 | 独立结果 | 学习处理 |
|---|---|---|---|
| `b5492bb7-20261009-232823-34fe`：三步模拟经营月报 | 8.0/10 | 独立 oracle 23/23；必要检查 26/26，语义 12/12 | 汇总步骤观察 1.0；另两步未评价；候选隔离，正式更新 0 次 |
| `1624c869-20261009-232919-0fe0`：主观设计建议 | 8.0/10 | 必要检查 7/7，语义 4/4；无独立标准答案 | 结果未知，不分配奖励，不蒸馏，正式更新 0 次 |

两次运行前后正式策略 SHA-256 均为 `bc60c6945a9af22b2443d24b507cbb58de28deda51a7acc7b893246226851003`，实际成本合计 ¥0.3129。两题同为 8 分但证据不同，直接揭示“高分就学习”的错误。独立算术只确认模拟数据汇总，不证明报告的商业价值。

原始证据：[HTTP 与模型实测报告](../out/outcome-evidence-smoke.json)、[交付指纹清单](evidence/outcome-evidence-files.json)。首页默认回放新版经营任务，并提供“同为 8 分，为何不学习？”对照；完整轨迹、对话、运行中心共用评价面板。历史记录明确标注采用旧协议，没有事后补写评价。

复现已有记录不会新增模型费用：

```bash
python tools/outcome_evidence_smoke.py --business-run b5492bb7-20261009-232823-34fe --unmeasured-run 1624c869-20261009-232919-0fe0
```

不传 ID 会创建两次真实运行，预算上限分别为 ¥1.20、¥0.60。第一次现场测试还发现 HTTP 去除末尾换行导致参考识别失败，已修正并覆盖回归；未修改旧运行记录来伪装成功。

本轮浏览器自动化因 Windows sandbox 初始化错误不可用，重置后仍失败；没有生成新版截图，也没有把脚本检查写成视觉验收通过。原有流动背景与交互结构保留，新增样式只作用于评价面板。S1 线上联调仍是原有未完成边界。

本地验证：263 项 pytest、31/31 自检、全部五组前端检查通过；六个页面 HTTP 200，静态脚本与资源完整。晋级测试用离线构造的物理产物与 20 个运行记录覆盖通过和拒绝路径，不冒充 20 次实际模型评测。两次模型实测的全部原始文件与报告列入新增 10 项指纹清单。
