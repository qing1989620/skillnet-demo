# 自然语言技能选择与执行边界：最终研究验证

日期：2026-10-14。对应完整交付版 `2026.10.14-complete.22`。本轮没有证明“技能网络会因持续训练而普遍变好”，因此训练候选未进入默认路由，也没有获得奖励。可以交付的改进是：完整公开失败证据、自然语言到真实文件的可重跑链路，以及经另一份新数据验证的登记程序执行前检查。

## 研究依据与产品定位

[Skill Following](https://arxiv.org/abs/2609.00549) 强调同任务的配对执行，避免把检索覆盖与实际帮助混为一谈；这启发本轮将所有任务、三组调用和物理产物一起报告。本实验主动提供提示，并非该论文自发检索条件下的 RAE 复现。

[Diversity-Aware Skill Routing](https://arxiv.org/abs/2609.05824) 已研究互补集合选择；[Skill-V](https://arxiv.org/abs/2610.11781) 已研究可证伪契约、版本更新与历史非回退。因此本产品不宣称首次提出技能图、契约或自我演化。近期工作也说明这些机制需要实测边界。[AgentAbstain](https://arxiv.org/abs/2607.10059) 区分应当执行与应当停止的情境，本轮据此分别计量有效任务交付与边界拒绝，不将两者合并成一个好看的分数。

SkillNet-S1 的产品价值仍是：为问题检索少量适用技能，把选择、执行、联网来源、产物、核验和积累呈现在同一链路；在 S1 身份与项目空间下保留用户的偏好和方法资产。研究成果是否进入这条链路，必须接受版本、对照、收益及回退约束。这里的贡献是项目内可复核的工程实现与验证，不是通用技能理论或学术优先权声明。

## 一、先冻结，再训练，再看新问题

此前条件收益研究把正确的三项清洗意图显式提供给选择器。本轮去掉这项便利：模型仅收到自然语言请求、真实 CSV 和共同登记程序说明，正确开关仅留给独立判据。

训练候选为冻结 multilingual-e5-small 表示上的九分类岭回归：八种技能开关组合与拒绝类。**训练标签是人工编写的请求语义，不是执行收益，更不是技能奖励。** 90 条开发请求拟合参数，18 条校准请求从 `0.01 / 0.1 / 1 / 10` 选择正则强度，平局选更大值。选中 `0.1`。没有更新 E5 参数，没有训练一个基础大语言模型。

24 条封存请求包含 16 道有效任务与 8 道含糊、矛盾、不支持或输入不可执行的边界任务。训练/校准沿用受控开发措辞，测试另写新措辞；请求和输入 SHA 全部不重叠。这是刻意检验措辞迁移，不能仅凭字节不重叠宣称完全语义独立。

有效测试测量来自整体留出的 [UCI Wine](https://archive.ics.uci.edu/dataset/109/wine)，仅使用 alcohol 数值。身份、分区、分组、重复、空值与污染记录是声明的受控变换，不是 Wine 原始数据的缺陷。不同任务可共享源测量，不能当作 24 个独立领域，也不能证明基础模型未见过公开数据。

三组实际 API 调用分别为：模型独立选择、加入最邻近的三个开发示例、加入训练头的建议。每题每组两次，共 144 次请求；三臂按任务轮换顺序，总体平衡调用位置。相同模型别名、温度、登记动作和输出预算；无重试。所有提示在首次测试执行前写入，均不含隐藏正确意图或本题执行结果。训练分数明确不是校准概率。

协议提前要求：同时超过两种对照至少 2 个百分点、任何有效任务配对不得退步、边界不能错误执行、输入 token 增幅不超过 15%，且需不可变模型修订证据。判据没有按结果修改。

## 二、实际结果：训练提示没有胜过强对照

| 方法 | 有效产物交付 | 边界正确拒绝 | 边界仍选择执行 | 格式/调用失败 | 输入 tokens |
|---|---:|---:|---:|---:|---:|
| 模型独立选择 | 32/32 | 9/16 | 7 | 0 | 35,590 |
| 加入检索示例 | 27/32 | 9/16 | 7 | 0 | 46,376 |
| 加入训练提示 | 30/32 | 9/16 | 6 | 1 | 42,256 |

每个有效任务的两次调用是重复观测，不能视为 32 个独立任务。训练提示相对独立模型为 0 胜、2 负、30 平，交付差异为 **−6.25 个百分点**，输入 token **+18.73%**。相对检索示例有 3 胜、0 负，但更强的独立模型对照已经达到 100%，因此不能挑选较弱对照宣布收益。

请求别名为 `deepseek-chat`，实际 144 次响应返回 `deepseek-flash`；提供方还返回 fingerprint，但它不是公开可验证的不可变模型修订。本报告不假定两个别名是不同实验模型。

训练头在校准标签上为 18/18，却在新措辞的 16 道有效任务上全部选择拒绝，独立交付 0/16；边界拒绝 8/8。最邻近单示例独立选择为 4/16 交付、1/8 边界拒绝。**过度拒绝不能作为安全能力提升。** 校准集与训练措辞接近，校准满分不足以证明泛化；不在这批测试上调整模型再宣称封存成功。

保留的格式失败为 `{"mask":0,"reject":true}`：拒绝时 mask 应为 null，严格解析拒绝这个矛盾动作，没有宽松修补、再请求或删除记录。总共保存 192 条结果：144 条 API 决策和 48 条离线候选/近邻决策。139 次实际子进程执行、257 个输出文件逐一核验。非法输入的失败文件和 stderr 也保留。

本轮十二门研究审计 **5/12**，完整性、开销公平性、精确模型版本、非回退、强对照增益、跨任务可靠性及正式一次性证书均未全部满足。奖励 **0**，正式路由没有替换。

## 三、只落地获得支持的边界检查

错误轨迹表明，模型会在无 test 行、局部分组全空或非数值的情况下仍选择执行。`reviewed_execution` 将登记动作作用于输入快照，检查投影后的分组和数值范围，绑定输入 SHA 与程序 SHA；不通过时在子进程启动前拦截。通过时执行同一份快照，再从实际文件核验结果。它复用此前独立定义的观测条件，是规则检查，不声称学习优于规则。

在看到 Wine 结果后提出的修正，不拿 Wine 充当独立新验证。另冻结 **12 道 UCI Glass 新输入 × 8 种动作 = 96 个动作**，在任何执行前保存全部检查结论。测量仅使用 [Glass RI](https://archive.ics.uci.edu/dataset/42/glass+identification)，同样声明受控分区与缺陷。为检测漏拦和误拦，连被拒绝的动作也在隔离的固定程序中强制执行，并由独立原始单元格与 Decimal 判据复核。

| 新验证结果 | 数量 |
|---|---:|
| 实际可执行动作 | 44 |
| 实际不可执行动作 | 52 |
| 错误拦截可执行动作 | 0 |
| 漏拦不可执行动作 | 0 |
| 程序退出与产物判据不一致 | 0 |

这支持登记程序在该有限验证集内的数据可执行性检查；没有统计保证任意输入都安全，没有提升有效任务交付质量，也没有证明训练有必要。检查不知道“只留最后一次”是否是用户真正要求，不能解决自然语言含糊、不支持操作或错误效果选择。原有主执行管线的声明式 `csv_group_numeric_coverage` 仍用于已登记聚合输入的执行前验收；新快照检查作用于本轮登记程序重跑服务，没有给任意生成代码套用未经验证的泛化规则。

## 四、产品中如何查看与复核

`/utility#semantic-study` 展示三组真实调用、原始失败、十二门与独立 Glass 验证。选择封存自然语言请求和第一次/第二次调用，可重新执行三组已记录决策，并比较独立模型增加数据检查后的行为。**这是旧 API 决策的新程序执行，不是新的 API 调用或在线模型推理。** 不接受任意代码、路径或客户端证书，不写正式库、个人数据或奖励。鉴权、并发限制、证据版本错误关闭和临时目录清理均在服务端实施。

全部请求、响应、模型权重、输入、协议和选择记录在 `assets/semantic-routing/v1`，物理程序与 CSV 在其 ZIP；Glass 验证在 `guard-v1`。来源 CC BY 4.0 署名随数据提供。没有提交 API Key、认证头或私人用户问题。历史 Windows stderr 可能保留作者实验工作区路径；API 返回诊断时会去除瞬时路径，实际 CSV 原文与 SHA 不改写。

```powershell
python tools/verify_semantic_routing.py --public assets/semantic-routing/v1
python tools/verify_reviewed_guard.py --public assets/semantic-routing/guard-v1
python -m pytest tests/test_semantic_study.py -q
```

冷克隆核验无需 API 额度、编码器推理或训练；只重读文件与独立复算，绝不执行 ZIP 内脚本。要重新运行付费研究，先在全新目录依次执行 `semantic_routing_lab.py prepare / train / run --work <新目录>`，预算为 144 次真实请求；旧目录不能无声覆盖或重试。Glass 的 `reviewed_guard_lab.py prepare / run` 只执行固定本地程序。

## 五、后续决策

保留既有混合检索和人工确认的个人偏好机制。用户问题是观察，明确偏好才是个人训练标签，真实产物对照才可能支持版本提升。下一步若继续研究，应扩展真实任务族、独立语言风格和来源，先证明选择有效且不过度拒绝，再测执行效用；不能通过扩大训练次数或挑选低分基线绕过当前失败。

本次浏览器自动化因工具内核路径错误不可用；已做真实接口、物理重跑与真实页面脚本 DOM 检验，未宣称完成本轮像素截图或实机触控验收。正式 PDF 是先前产品说明，本轮研究更新在这些 Markdown 文档及在线研究页。

本轮本机 Windows / Python 3.12 全量回归 1,244 项通过，自检单独复验 31/31。前端静态、现有交互检查与新旧研究页 DOM 均通过；CI 另配置 Windows / Linux 的冷证据核验，本地通过不等于远端 CI 已完成。
