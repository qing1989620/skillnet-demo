# 从技能声明到可执行能力边界

2026-10-12。本轮逐段阅读两张长图，并核验 Contract2Tool、SIGIL、ASSAY、ReuseRL、PolySkill、SkillHEX 的方法。论文到实现的逐项映射见 [研究核验](capability-kernel-research.md)。本次重点是让条件真正改变执行，而不是只给状态报告换名字。

## 已进入执行链的机制

- 计划声明 `requires/ensures`，服务端在执行前冻结谓词、输入输出文件名和 SHA。支持 8 类有限文件条件；解析、上限和不支持条件返回 unknown，不猜测通过。
- 代码生成前读取沙箱将使用的真实输入副本，核对版本与条件。failed/unknown 阻断，留下零次代码生成的记录；不把输入问题误算成技能负贡献。
- 规划组合只按上游声明的保守蕴含关系推导，列出具体条件缺口。执行时重新读文件，不拿计划承诺当事实；并行生产者同名版本有歧义则阻断，不能按完成顺序任选。
- 真实产物按效果条件复核，失败进入修复且阻断下游。执行过程中不能放宽已冻结契约，登记产物指纹必须与检查快照一致。
- 公开科研场景叠加宿主定义的条件与独立结果复算，模型不能删除。结果判据在步骤内就核验，避免把 `0.90 → 0.9` 的原值漂移传到后续步骤。
- 首页、工作台、运行详情与能力报告展示声明、实际准入、后置效果、独立结果和缺口；内核实验室/评估实验室展示反例实验。球体和原七阶段回放保留。

## 实验与失败记录

固定代码实验实际运行 39 个 Python 子进程：11 类公开模拟输入 × 3 实现 × 2 策略。准入策略将代码调用从 33 降至 6，违规输入执行从 24 降至 0，违规输入生成指标从 15 降至 0；6 次有效任务机会误阻断为 0。有效输出独立正确仍为 5/6：错误比较符通过结构检查，却被阈值边界反例拒绝。两个正确实现仅在两个共同有效探针上一致，没有做普遍等价或自动去重。见 [完整冻结实验](evidence/capability-probes.json)。

## 验证与边界

本地 474 项 Python 回归通过、31/31 离线交付自检通过；8 组 Node 命令覆盖渲染、七阶段、球体生命周期、请求竞态和异常数据。按用户指定的 [BadGoods 前端审查助手](https://github.com/BadbotAI/BadGoods/blob/main/skills/review-frontend-production/SKILL.md) 建立全站台账，第三方技能未重新分发。

真实浏览器检查六页的 1440×900 与 390×844 首屏，全部无页面水平溢出；验证首页背景延续、七阶段暂停/定位、球体搜索/键盘焦点、手机会话抽屉关闭返回焦点。记录见 [浏览器观测](frontend-audit/browser-observations.json)。这不代替全视图错误状态、200% 缩放、读屏、性能预算和生产验收；审计台账保留这些未测项。

本轮实现的是有范围的状态契约和反例证据，尚未实现学习式因果转换概率、全局最小能力基或无限任务空间的可达证明。有限图的条件缺口不等于智能体不会。奖励仍由原十二道 AND 门约束，S1 线上联调仍需公司真实接口和环境。
