## 零、病根诊断（先承认问题）

对全库做了一次批判性审查，结论是：**没有任何代码被执行过**——`subprocess` / `exec` 零命中。

| 环节 | 声称 | 实际 |
|---|---|---|
| 执行 | 技能驱动执行 | 一次 LLM 调用写出整份方案文本；技能的 steps/pitfalls/verification 只是**提示词素材** |
| 评估 | 主客观双线 | 与被评者**同一模型**自评；参照点取自同一批被注入的技能（循环论证） |
| 编排 | 依赖图驱动执行 | 顺序**只写进展示字段**，执行时只传技能名列表 |
| 进化 | 技能持续沉淀 | 新技能当次不再执行、无来源追溯；质量靠关键词启发式 |
| 产物 | 交付物清单 | 清单是**承诺**，不是交付（后已单独修复） |

对照 Anthropic 官方 Agent Skills 定义，本项目缺的正是两条最核心的：
**技能是可执行的程序性知识**（可附带脚本由环境运行，只有输出进上下文）、
**Run → Validate → Fix → Repeat** 的迭代方式。诊断结论写入 commit message 存档。

## 一、真实执行层（新增）

### `skillnet/sandbox.py` —— 受控执行沙箱
- 子进程 + 独立临时工作目录 + 超时强杀 + `-I` 隔离模式
- **环境变量白名单**：不继承 API Key 等任何凭据；HOME/TMP 指向工作目录
- 自动收集运行期新生成的文件（图片 / 表格 / 数据 / 代码）
- 错误分类：`syntax` / `import` / `exception` / `timeout`（供修复策略区分）
- 安全边界**写在模块 docstring 与 README**：面向可信模型产出的分析代码，
  不是对抗性隔离；不主动授予网络，但无法在内核层阻断；生产需容器级。

### `skillnet/executor.py` —— 技能驱动的执行与修复
- 技能契约三件套直接进提示词：`steps`（该怎么做）/ `pitfalls`（别踩什么坑）/
  `verification`（怎么算做完）
- 流程：生成代码 → **本地语法预检**（语法错不进沙箱，更快定位）→ 沙箱真跑 →
  失败则把「真实错误 + 该技能已知陷阱」一起交给模型修复（最多 2 次）
- **技能验收**：用 `verification` 逐条核对产物，要求引用产物中的具体证据、
  不得推测；未满足如实标 FAIL
- 步骤选择器：优先分析 / 计算 / 验证类步骤，跳过文献 / 写作类（保证演示稳定产出）

### 接入闭环与前端
- `/api/demo` 扩为 **7 阶段**：检索对比 → 策略选择 → 编排 → 执行盲评 →
  **真实执行（沙箱）** → 反馈回流与蒸馏 → 本次产出
- 前端该阶段展示：尝试轨迹（失败→修复→成功）、完整代码（可展开）、
  真实运行输出（终端风格）、**内联图像产物**、技能验收清单逐条 PASS/FAIL + 证据
- `/api/artifact` 支持二进制图片（此前纯文本读取会把 PNG 读坏）

## 二、技能对照实验（回答「核心是什么」）

新增 `POST /api/execute_one`（单步执行，可选技能约束），演示页一键对照：
**同一步骤、同一模型，唯一变量是「有无技能约束」**。

实测（剂量-响应探索性分析，`eda-profiling`）：

| 指标 | 有技能 | 无技能（裸模型） |
|---|---|---|
| 生成代码规模 | 10310 字 | 6436 字 |
| 运行输出信息量 | 4000 字 | 1473 字 |
| 落盘真实产物 | 3 个 | 2 个 |
| 技能验收 | 2/3，逐条带证据 | 无验收标准 |

有技能时的验收证据示例：「corr(dose,log10(dose))=0.7081，标注高度共线」、
「CV>15% 建议核查重复；共线性建议不同时建模」。
**技能带来的不是更长，而是该做的检查做了没有、该避的坑避了没有、证据在哪。**

## 四、过程中修复的真实缺陷（全部实测发现）

1. `max_tokens=3000` 使科研代码被截断 → 结尾缺 ``` → 代码提取失败 → 三轮白跑；
   提到 7000，并把围栏未闭合 / 无围栏两种情况写进提取逻辑
2. 验收调用返回的顶层键是 `checklist` 而非 `checks` → prompt 明确 schema +
   代码宽容解析（checks/checklist/items/results/verification）
3. f-string 内 JSON 大括号未转义 → `Invalid format specifier`
4. 沙箱 workdir 传相对路径被二次解析 → 统一 resolve 为绝对路径
5. `save_bundle` 对二进制产物会以文本覆写 → 增加 `_copy_only` 分支
6. 沙箱产物文件名出现双下划线 → 前缀拼接统一

## 五、已知边界（诚实声明）

1. **沙箱安全等级**：面向可信代码，非对抗性隔离。生产必须容器化。
2. **执行范围**：目前只挑方案中**一步**落地为可运行代码（控制成本与时长），
   而非全流程分步执行。全流程分步执行是下一步（v0.7）。
3. **模拟数据标注**：无真实数据时要求代码显式标注「模拟数据」，
   验收员也据此判定；但**无法在技术上阻止模型把模拟结果写成结论**——
   这需要产物级数据溯源（下一步）。
4. **技能验收的主观性**：验收判定仍由 LLM 完成，虽然强制要求引用产物证据，
   但仍是判断而非证明；可程序化的验收项（如图表存在性、CSV 行列数）应逐步改为代码判定。
5. **对照实验样本量**：目前是单次对照展示，不是统计意义上的评估；
   要下结论需要多任务多轮次（沿用实验三的 bootstrap 口径）。
